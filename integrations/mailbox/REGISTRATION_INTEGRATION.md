# OpenAI 注册助手集成说明

## 功能概述

注册助手现在作为独立 Dashboard 入口运行，与 Mailbox、Bugteam 同级显示在主面板右上角，实现浏览器自动化注册流程的手动辅助界面。

## 集成的文件

### 后端逻辑
- **src/operations/registration-flow.cjs**: 注册会话状态机；“注册并导入 Codex”委托 Manager OAuth，缺少该能力时保留 Playwright 后备流程；“注册 GPT”只打开外部浏览器
- **src/operations/virtual-display.cjs**: 无 `DISPLAY` 时按会话启动/释放隔离的 Xvfb 虚拟显示
- **src/operations/registration-manager.cjs**: 会话管理器，支持最多3个并发注册会话
- **src/operations/liye-phone-order.cjs**: 复用之前仓库的 LIYE 人工取号/收码状态机
- **src/operations/registration-email-code.cjs**: 按邮箱匹配已导入来源，支持注册启动后的持续查询，以及 GPT 外部浏览器打开后的单次邮箱验证码查询
- **src/operations/registration-key-pool.cjs**: 使用扩展宿主服务器上的 `0600` 文件保存接码 Key 池，旧版 VS Code SecretStorage 仅作为一次性迁移/恢复来源，只向面板展示脱敏值
- **src/mailbox/server-storage.cjs**: 以扩展宿主服务器的 `globalStorageUri` 保存共享邮箱池、邮箱凭据和注册助手非敏感记录，并一次性迁移旧客户端状态
- **src/operations/registration-phone-sources.cjs**: 接码来源注册表（当前提供 LIYE，保留后续扩展入口）

### 前端集成
- **src/ui/integration.cjs**: 
  - 添加了 `RegistrationManager` 实例
  - 添加了消息处理器（registrationCreate/Submit/Cancel等）
  - 修复了参数名匹配问题（phoneNumber/otp）
  - 同时注册 `mailbox` 和 `mailbox-registration` 两个 Dashboard 入口，并让两个面板共享邮箱/注册会话状态
  
- **src/ui/panel.cjs**:
  - 添加了注册助手面板UI（CSS + HTML渲染）
  - 提供独立的注册助手界面，可按邮箱库筛选、选择已导入邮箱，或直接输入新邮箱
  - 添加了所有交互事件处理器（toggle/create/submit/cancel/cleanup）
  - 添加了 input 事件监听器同步 registrationEmail
  - 增加邮箱验证码显示框、重新查询按钮、手机号/短信验证码显示框和复制按钮
  - 增加接码来源下拉框、网页入口、订单倒计时和服务器侧 Key 池维护
  - 提供“注册并导入 Codex”和“注册 GPT”两条注册路线，并在邮箱池显示“GPT 已注册”与“Codex 已接入”状态
  - 注册会话子卡片可直接删除对应邮箱库条目；顶部支持清除所有注册记录

## 使用流程

1. 在 Manager 主面板右上角点击独立的"注册助手"按钮
2. 在邮箱库中筛选并选择已导入邮箱，或直接输入新邮箱；已经导入 Codex 的邮箱会自动从注册邮箱库中隐藏，直接输入也会被拦截。选择只会填入地址，不会自动开始注册
3. 点击“注册并导入 Codex”或“注册 GPT”：“注册并导入 Codex”在 Manager 提供能力时复用与 Mailbox“Codex 导入”相同的 OAuth 流程；“注册 GPT”只运行注册页面辅助流程，不调用 Codex OAuth。
4. “注册并导入 Codex”路线：
   - 使用 OAuth 授权入口打开外部浏览器，通常会先进入 `https://auth.openai.com/choose-an-account`；
   - 当前邮箱会作为 `expectedEmail` 校验，避免误导入其他账号；
   - 邮箱、密码、手机号、验证码、姓名年龄和最终授权均在 OAuth 浏览器窗口中由你完成；
   - 面板只查询并显示最近 30 分钟邮箱验证码，接码区域只负责取号/读码和复制，不会把内容自动提交到外部浏览器；
   - OAuth 回调完成后，Manager 自动导入账号并刷新额度，不需要再次点击“Codex 导入”。
5. “注册 GPT”路线由 Manager 打开 `https://auth.openai.com/create-account` 外部网页；密码、邮箱码、手机号、短信码和最终确认均由你在网页中手动完成，助手不会调用 OAuth 回调、读取或提交网页表单。页面成功打开后，助手会自动查询一次最近 30 分钟的邮箱验证码，但不会启动持续 watcher；之后邮箱查询/刷新、取号、换号和取消仍由你点击面板按钮控制。点击“完成 GPT 注册”后记录 GPT 注册成功，但邮箱查询和接码辅助仍保持可用，供后续 Codex 导入使用。点击“导入 Codex”后，注册卡片会显示“终止 Codex 导入”，只终止当前邮箱发起的 OAuth 导入，不影响其他导入渠道。邮箱池会持久化该邮箱的 GPT 注册状态；已注册 GPT 但尚未接入 Codex 的邮箱仍可选择，已接入 Codex 的邮箱会隐藏。
6. 在接码区域选择来源和 Key 后点击“开始取号”。Key 池默认收起，点击“管理接码 Key 池”即可展开维护；如果存在可用 Key，面板会自动选择第一个可用项，选择器最多显示前 5 个可用 Key，其余仍保留在 Key 池维护区。点击任一路线按钮后邮箱会自动复制；GPT 路线只有在你点击“开始取号”后才访问接码来源，收到手机号后该订单才会自动轮询短信，并可随时点击“重新取号”或“取消取号”。完整且格式有效的邮箱验证码、手机号和短信验证码会按原路线自动复制到剪贴板，同时保留手动复制按钮；GPT 路线不会自动复制邮箱码、手机号或短信码。复制由扩展宿主通过 VS Code 剪贴板 API 执行，不依赖鼠标是否停留在当前面板；遇到剪贴板瞬时失败会自动短暂重试，最终失败时提示手动复制。面板显示的成功率只来自接码平台返回的数据；平台未提供时显示“平台未提供”，不计算本地成功率。
7. 如果号码不可用，面板会保留接码平台的错误原文；只有你点击“重新取号”才会换号，“取消取号”也只在你点击后执行。无需再点击“确认号码”或“读取验证码”。
8. Key 只有在真正收到短信验证码后才会从池中移除；换号、取消、取号失败、超时或未收到验证码都会释放回可用状态。LIYE 已失败或已结束且没有验证码的历史订单不会被当成可恢复订单；如果平台返回“订单上游缺失”，本次轮询会停止并释放 Key。GPT 注册完成后不会强制取消仍在运行的订单，导入期间仍可由用户手动换号或取消；清除记录或关闭助手时会释放活动订单和 Key，终止 Codex 导入只停止 OAuth，便于稍后重试。
9. 如果换号请求与平台收到短信同时发生，平台返回“验证码已到达”的 409 时会重新查询当前订单；已有码则直接显示，未有码则恢复轮询，不会让后台读取任务悄悄停止。
10. 收到短信验证码后会 best-effort 结束 LIYE 旧订单；即使平台拒绝对已收码订单重复取消，下一轮取号也会跳过所有已有验证码的历史订单，不会复用旧号码。
11. 如果 Manager 不支持 OAuth 导入，“注册并导入 Codex”也保留 Playwright 页面状态检测后备流程，注册完成后需从邮箱池手动导入 Codex；“注册 GPT”始终不调用 OAuth 导入。
12. 注册会话卡片中的“删除邮箱”会直接删除对应邮箱库条目；如果该邮箱仍有活动注册会话，会先自动取消该流程；关闭注册助手界面也会取消未完成的 GPT 手动会话；顶部“清除所有记录”会取消活动会话并清理全部注册会话卡片，不删除邮箱库。

### 无图形界面的远程环境

只有在“注册并导入 Codex”因 Manager 不支持 OAuth 而进入 Playwright 后备流程时，如果 VS Code 扩展宿主没有 `DISPLAY`，注册助手才会尝试启动一个独立的 `Xvfb` 虚拟显示。GPT 路线使用 Manager 打开的外部浏览器，不启动 Playwright 或 Xvfb。该虚拟显示只服务当前注册会话，使用 `-nolisten tcp`，不会修改服务器全局配置或当前扩展宿主的 `DISPLAY`；会话结束后会释放它。

`Xvfb` 是不可见的虚拟桌面，所以浏览器不会弹到你的电脑上。它适合验证浏览器能否启动和记录页面状态，但如果出现 Cloudflare，用户也无法点击。此时流程会立即失败，并记录明确日志：“当前浏览器运行在 Xvfb 虚拟显示上，窗口不可见，你无法点击完成验证”；请改用 X11 转发、xpra/noVNC 或真实 `DISPLAY`。

如果不希望自动启动虚拟显示，可设置 `CODEX_MAILBOX_HEADLESS=true`，流程会直接使用无头浏览器。设置 `CODEX_MAILBOX_HEADLESS=false` 会强制尝试有头模式；没有真实 `DISPLAY` 时仍会先启动 Xvfb。若服务器未安装 `Xvfb`，会记录启动失败并回退到无头模式。

OAuth 主流程使用 Manager 的外部浏览器，因此 Cloudflare 由该浏览器中的用户正常完成；不会自动点击或绕过校验。只有 Playwright 后备流程才使用下面的 `DISPLAY`/Xvfb 配置，并持续记录 Cloudflare 状态。

## 技术要点

- **并发控制**: 最多支持3个会话同时进行
- **状态同步**: 通过 EventEmitter 实时更新前端状态；邮箱池和非敏感注册记录以服务器侧文件为共享权威
- **错误处理**: 会话失败时显示错误信息，支持清除记录
- **双路线**: “注册并导入 Codex”与 Mailbox“Codex 导入”共用 Manager 的 PKCE、回调监听、账号邮箱校验和导入逻辑；“注册 GPT”仅走 Manager 外部注册浏览器，不创建 OAuth 回调监听
- **后备状态检测**: 没有 Manager OAuth 能力时，根据可见输入框、页面文本和授权按钮识别密码、邮箱码、手机号、短信码、姓名年龄和授权阶段
- **人工确认**: OAuth 主流程中的表单和最终授权由外部浏览器中的用户完成；GPT 路线的注册表单也完全由外部浏览器中的用户完成；面板中的邮箱码、手机号和短信码只显示/复制，不会自动提交
- **邮箱验证码**: 仅查询已导入 provider 返回的带收到时间邮件，按时间倒序取30分钟窗口内最新验证码
- **邮箱刷新**: Codex 路线启动后自动查询；GPT 路线在外部注册网页成功打开后自动查询一次，之后点击“查询邮件/重新查询”才启动或刷新持续 watcher，并可点击“停止查询”，完成 GPT 注册后仍可继续手动查询，不会创建重复轮询器
- **剪贴板复制**: 邮箱地址统一由扩展宿主调用 VS Code 剪贴板 API自动复制；Codex 路线还会自动复制邮箱验证码、手机号和短信验证码，GPT 路线只保留这些内容的手动复制；Webview 只发送复制请求，写入失败会短暂重试
- **接码 Key 安全**: Key 原文保存在扩展宿主服务器的 `0600` 文件，旧版 SecretStorage 仅作为一次性迁移/恢复来源；面板和诊断日志只显示脱敏值；成功收码后移除，其他结束路径释放
- **注册记录安全**: 跨设备只恢复邮箱、阶段和结果摘要；密码、手机号、邮箱码、短信码和 OAuth token 不写入服务器记录。扩展重启或换设备时，正在运行的浏览器流程标记为未恢复，需要重新开始
- **注册状态**: 注册完成后，同地址邮箱池记录写入 `gptRegistered`/`gptRegisteredAt`；该状态与 Manager 账号目录提供的 `Codex 已接入` 独立显示
- **记录清理**: 单个注册卡片只对邮箱库中的邮箱显示直接删除按钮；删除邮箱会取消同邮箱的活动注册会话；顶部批量清理会先取消活动会话再移除全部注册记录
