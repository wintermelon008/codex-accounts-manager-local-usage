# 变更日志

## 维护约定

- `announcements.json` 只保留当前版本的更新公告（`releaseVersion` + 新 `id`），发布新版本时旧版本更新说明可直接移除对应项，避免历史版本在弹窗中继续出现。
- 历史版本正文统一写在本文件，按版本追加条目，不做删除。
- 详情可按 `releaseVersion` 反查本次发布公告对应的 `id` 与变更内容。

## 0.1.16-local.27（2026-07-21）

### 本地定制变更

- 将无感切号的可选 `1%` 保护调整为 Free 优先：经实际有效五小时/周窗口校验的 Free 账号在五小时额度到 `1%` 或以下时，优先切到池中最近两分钟内刷新、五小时额度最高且周额度仍安全的 Free 账号；没有合格 Free 时才回到原有混合 windowed/reserve 选择。
- 将 runtime 结构化 `usageLimitExceeded` 接入同一选择器：无需等待下一次配额刷新，受限普通会话会以中断后 Continue 的既有语义恢复，Goal 继续使用暂停/恢复路径；远端窗口若已落后于共享活动账号会直接收敛，不重复选号。
- 新增只在该开关开启时运行的轻量 runtime 监测器：每两秒读取固定大小状态 JSON，不读取 thread ID、会话正文或历史，不保存增长型缓存；选择失败 10 秒退避，状态 RPC 失败 30 秒退避，并以共享 `seamless-switch` 租约避免多宿主重复决策。

### 验证说明

- 覆盖 Free 最高额度优先、Free 候选的 1%/周额度/两分钟新鲜度排除、无 Free 时混合回退、运行时限额事件、跨窗口收敛、轮询关闭与退避的回归测试。
- 本地构建版本升级为 `0.1.16-local.27`，继续基于上游 `0.1.16`。

## 0.1.16-local.26（2026-07-20）

### 本地定制变更

- 修复本地用量把重复 `token_count` 上报反复累加的问题：改为按每个 rollout 的 `total_token_usage` 累计高水位计算增量，重复值和过期回退值不再增加统计。
- 修复 multi-agent spawned subagent 复制父会话历史导致的巨额重复计数：首个 `session_meta` 标记为子代理时，复制前缀只建立累计基线，从子代理自己的 `trigger_turn` 边界后才计入新增。
- 排除晚于扫描快照时间的事件，并升级本地聚合缓存 schema/文件名，使旧的错误缓存不会继续展示 15 分钟。

### 验证说明

- 新增累计重复、过期回退、跨日基线、未来事件和子代理继承历史回归测试。
- 以 2026-07-20 17:09:50（Asia/Shanghai）为固定截点扫描真实会话集，扩展统计得到 `291,687,461` token；独立 `jq`/`awk` 高水位与子代理边界计算在 input、cached input、output、reasoning output、total 和 event count 上逐项一致。
- 本地构建版本升级为 `0.1.16-local.26`，继续基于上游 `0.1.16`。

## 0.1.16-local.25（2026-07-19）

### 本地定制变更

- 修复本地用量扫描导致 Remote Extension Host 内存持续增长并触发 OOM 重启的问题。
- 扫描前按保守 mtime 窗口排除不可能包含近 14 天事件的旧会话文件；流式读取时只解析 `turn_context` 与 `token_count`，不再为会话正文和工具输出分配 JSON 对象图。
- 复用时区日期格式器，避免每条 token 事件重复构造 `Intl.DateTimeFormat`；本地会话原始内容与缓存隐私边界保持不变。

### 验证说明

- 真实 331 MB 活动会话集在 512 MB Node 堆限制下完成扫描，峰值 RSS 约 100 MB，122 个来源文件的现有窗口统计保持可用。
- 本地构建版本升级为 `0.1.16-local.25`，继续基于上游 `0.1.16`。

## 0.1.16-local.24（2026-07-19）

### 本地定制变更

- 修复删除全部受管账号后的首次无感切换：从当前有效 `auth.json` 建立仅驻留内存的回滚快照，经 live app-server 身份校验后执行切换，失败时恢复旧身份。
- 强化 Mac、Windows 与 Remote-SSH 多宿主一致性：账号索引/token/配额镜像使用原子写入、共享租约、三方合并与 stat/revision 轮询，减少新导入账号、额度和活动账号被旧缓存覆盖的问题。
- 本地用量 Dashboard 会采用其他宿主写入的更新聚合，并在 `nextRefreshAt` 主动刷新；扫描租约可过期回收，缓存继续只保存匿名汇总。
- 无感分档新增 `1%`、`2%`、`3%` 储备阈值，并按真实额度窗口区分分档账号、无五小时窗口的储备账号和数据未知账号，不再依赖 Free/Plus 套餐标签猜测。
- 普通自动调度优先轮换分档账号，全部达到阈值后才启用周额度最高的储备账号；储备账号到达阈值时优先回到已恢复的分档账号，手动切号逻辑保持不变。
- 1% 紧急切换优先选择仍安全的储备账号，再回退到五小时额度高于 1% 的分档账号；普通会话 Continue、持久 Goal 暂停/恢复和 workspace 权限保持语义不变。
- 补充冷启动、多窗口收敛、混合账号选择、本地用量同步与隐私边界的回归测试和中英文文档。

### 构建说明

- 本地构建版本升级为 `0.1.16-local.24`，继续基于上游 `0.1.16`。
- 恢复 `.eslintrc.json` 兼容的 ESLint 8，并固定可在当前 Node 18 发布环境运行的 VSCE 2.32/兼容 Cheerio；运行时依赖不受影响。
- ESLint 固定在兼容 `.eslintrc.json` 的 8.57.1；VSCE/Cheerio 固定在支持当前 Node 18.19 构建宿主的版本，避免宽松依赖漂移导致 lint 或打包命令无法启动。
